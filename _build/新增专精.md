# 加一个新专精

以「火法」为例。全程改 3 个文件，跑 1 条命令。

---

## 0. 先做功课（这步最花时间，也最值钱）

不要先动代码。先把这四样查清楚，查不到的就**留空标待补**，不要用"通常认为"填。

| 要查的 | 去哪查 | 注意 |
|---|---|---|
| 技能中文名 + 图标 | Wowhead 接口（见下） | **不许自己编译名** |
| 天赋使用率 | Murlok.io 对应专精 top50 | 看实际佩戴分布，不看理论最优 |
| 本版改了什么 | 官方补丁说明 | 移除了什么比新增了什么更重要 |
| 梯队 | Icy Veins PvP 梯队表 | 只当参考坐标 |

拿技能官方数据：

```bash
curl -s "https://nether.wowhead.com/tooltip/spell/133?dataEnv=1&locale=4"
# → {"name":"火球术","icon":"spell_fire_flamebolt","tooltip":"..."}
```

`locale=4` 是简体中文。返回的 `icon` 就是图标文件名，下载到本地：

```bash
curl -o site/assets/icons/spell_fire_flamebolt.jpg \
  https://wow.zamimg.com/images/wow/icons/large/spell_fire_flamebolt.jpg
```

> 图标必须存到本地。国内访问 zamimg CDN 不通，直接引 CDN 的话手机上是一片空白——
> 第一版就栽在这里，而且 `onerror` 把失败藏起来了，看着像"没做图标"。

技能说明也要进 `site/assets/js/skdb.js`（浮窗读它）：

```js
'火球术': { icon:'spell_fire_flamebolt', meta:'2.25秒施法 · 40码', desc:'接口返回的 tooltip 正文' },
```

---

## 1. 写内容模块

```bash
cp _build/content/_TEMPLATE.js _build/content/fire-mage.js
```

模板里每个字段都有注释，照着填。**文件名就是页面文件名**：`fire-mage.js` → `fire-mage.html`。

内容不用一次填满。六个轴里先填哪几个都行，没填的页面上会显示「资料待补」。
建议顺序：**骨架 → 对阵 → 题库 → 手法 → 天赋 → 装备**。骨架那句话没想清楚，后面写什么都是散的。

---

## 2. 加页面配置

`_build/pages.js` 的 `PAGES` 数组里加一条：

```js
{
  file: 'fire-mage', kind: 'spec', cls: 'mage', spec: 'fire',
  h1: '火法 PvP 判断训练器', short: '火法',
  icon: 'spell_fire_firebolt02', tier: 'S', color: '#3FC7EB',
  crumb: ['法师', '火焰'],
  store: 'banyeFireMagePvP1207',   // localStorage 键，必须全站唯一
  quizSec: 's4',                    // 「判断训练」是第几个原始章节
  catLabel: { general: '通用手法' },
  done: { hi: '…', mid: '…', lo: '…' },   // 答完 10 题的三档评语
  talent: { rows: [ { lb:'英雄天赋', vv:'…' } ], todo: TAL_TODO },
},
```

---

## 3. 在注册表里点亮

`site/data/registry.js` 里找到 mage → fire，改两个字段：

```js
{ id:'fire', n:'火焰', en:'Fire', role:'dps', tier:'S',
  ic:'spell_fire_firebolt02',
  page: 'fire-mage.html',        // 从 null 改成文件名
  st: [2, 2, 2, 1, 0, 2] },      // 六轴完成度：骨架/手法/对阵/天赋/装备/训练
}
```

改完首页矩阵里这一格就从灰色变成可点，覆盖度数字、sitemap、每页底部的「换一个练」全部自动跟上。

---

## 4. 构建

```bash
cd _build && node all.js
```

会依次跑：样式 → 专精页 → 首页 → sitemap → 自检。
自检查三样：**本地引用有没有坏链、JS 有没有语法错、每页是不是恰好一个 h1**。
最后一行是 `✅ 全部通过` 才算完。

## 5. 本地验一眼

```bash
cd site && python3 -m http.server 8899
```

打开 <http://localhost:8899/>，重点看四处：

- 首页矩阵里新专精是不是亮的
- 新页面的技能图标有没有出来（缺图标会是空白，不会报错）
- 点开「判断训练」题库能不能加载
- 手机宽度下排版有没有塌

## 6. 发布

```bash
git add -A && git commit -m "新增火法训练器" && git push
```

GitHub Pages 一两分钟自动生效。

## 文案调性

全站统一，写内容前先过一遍：

- **只写信息，不写编辑方针。** 没有的内容标「待补充」就够了，不要解释为什么没有、打算怎么补。
- **不写界面说明书。**「点标题看细节」「这页只放 30 秒能看完的东西」——用户会自己点，不用教。
- **引导语能删就删。** 版块标题说清楚了就不要再铺垫一段。
- **陈述句优先，不用第一人称表态。**「我推的」写成「编者推导」，「我会立即移除」写成「将立即移除」。

判据很简单：**这句话删掉，读者会不会少知道一件事？** 不会就删。

## 常见坑

**图标不显示。** 十有八九是没下载到 `site/assets/icons/`。`onerror` 会把失败的图藏起来，
所以看着像"没配图标"而不是"图裂了"。查：`ls site/assets/icons/ | grep <图标名>`。

**题库正解全在同一个位置。** 不用管——选项顺序在运行时打乱，`r` 写真实下标就行。
第一版 240 道题里 95% 正解是 B，就是因为当时没打乱。

**改了内容页面没变。** 你可能改的是构建产物。内容源在 `_build/content/`，
`site/data/specs/` 和 `site/*.html` 都是生成出来的，会被覆盖。

**新加的章节点不开。** 章节 id 要和 `nav` 里的 `s` 对上。构建会自动插入天赋/装备两栏并重新编号，
`nav` 里不用写这两栏，也不要自己写 ①②③ 圈号。
