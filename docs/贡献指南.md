# 贡献指南

## 最有用的三种贡献

按价值排：

1. **内容纠错** —— 技能机制写错、数据引用错、跟游戏内不符。**有出处的优先处理。**
2. **认领一个专精** —— 还有 36 个专精、31 组组合没开工，见 [路线图](ROADMAP.md)。
   完整步骤在 [新增专精](新增专精.md)。
3. **补齐存量** —— 已上线的六个训练器，装备的属性排序全部欠着、天赋树没整理。
   这比新开一个专精更值得先做。

## 两条内容纪律

改内容之前先看这两条，破了不会合。

**一、不编中文技能名。**
查 Wowhead 官方接口拿简体中文名，查不到就用英文原名并在页面上注明。

```bash
curl -s "https://nether.wowhead.com/tooltip/spell/133?dataEnv=1&locale=4"
# → {"name":"火球术","icon":"spell_fire_flamebolt","tooltip":"..."}
```

第一版就是靠猜译名翻过车——毒伤 / 影袭 / 秘密技艺全是编的，实际是刺骨 / 暗影之刃 / 影分身。

**怎么确认一个译名不是编的**：给候选 spell id，先查 `locale=0` 拿英文名回验，
与目标一致才采信 `locale=4` 的中文名。工具在 `_build/tools/`：

```bash
python3 _build/tools/verify-spell-ids.py out.json      # 候选 id → 双语回验
python3 _build/tools/verify-skill-names.py skdb.json out.json  # 核 skdb 里的名字
```

已验证过的记在 `_build/tools/verified-names.json`（123 条），不用重复验。

**两个坑**：
- **图标不能反推名字。** 多个技能共用一个图标是常态
  （Thick as Thieves 与 Tricks of the Trade 同图标；猎人的逃脱用着 `ability_rogue_feint`）。
- **同名不同技能。** 「恶魔变形」浩劫版和复仇版是两个技能，图标和效果都不同。

**二、实测和推导分开写。**
首页有专门一段划这条线。技能说明、天赋使用率、版本改动、梯队 = 有出处；
判断框架、控制链结构、题目设计 = 编者推导。
**不写具体秒数和装等数字**——数值每次平衡都在动，写死了下个补丁就是错的。

## 文案调性

- **只写信息，不写编辑方针。** 没有的内容标「待补充」就够了，不要解释为什么没有、打算怎么补。
- **不写界面说明书。**「点标题看细节」这类——用户会自己点。
- **引导语能删就删。** 版块标题说清楚了就不要再铺垫一段。
- **陈述句，不用第一人称表态。**「我推的」写成「编者推导」。

判据：**这句话删掉，读者会不会少知道一件事？** 不会就删。

## 补丁更新怎么走

新补丁上线后，天赋分布、属性、梯队全部作废。**不要手工重来一遍**：

```bash
python3 _build/tools/refresh.py              # 全部专精，约 1 分钟
python3 _build/tools/refresh.py arms-warrior # 只看一个
python3 _build/tools/refresh.py --no-fetch   # 用上次抓的 HTML，不重新请求
```

它会抓页面、解析、下新图标、和上一版比对，然后**只报告需要人改的地方**：

- 哪几条描述的原文变了 → 那几条要重译，没变的不动
- 哪几格进出了「需要判断」区间 → `pages.js` 的 picks 要改
- 属性排序变没变 → `gear` 要不要调
- 英雄天赋两条线的分布变没变

**新数据不会直接覆盖旧文件**，都放在 `/tmp/wowcamp_refresh/`，确认后自己拷。

两个设计上的讲究：

- **边界抖动会被单独标出来。** 使用率在 20%/85% 线附近浮动几个百分点，
  格子就会进出区间——那是噪音不是变化。报告只把幅度 >5 个百分点的算作真变化。
- **英雄天赋的口径跟站上一致，并且会打印出来。** 一边倒（如 50/0）只排除没人走的那条线；
  真二选一（如武器战士 29/21）整棵树都不计逐格分歧。口径不一致的话，
  报告出的格数就没法直接对着改页面。

## 动手之前

**别改 `*.html` 和 `data/`**，那些是构建产物，下次构建会覆盖。
源文件在 `_build/`：

| 改什么 | 改哪里 |
|---|---|
| 某个专精的内容 | `_build/content/<id>.js` |
| 页面标题、图标、梯队、天赋 | `_build/pages.js` |
| 专精 / 组合清单与完成度 | `data/registry.js` |
| 天赋树布局与使用率 | `_build/tree/<页面>.json`（别手改，用 `_build/tree/_parse.py` 重抓） |
| 样式 | `_build/core.css`、`_build/overrides.css` |
| 交互引擎 | `assets/js/app.js`、`assets/js/home.js` |
| 站名、域名 | `_build/config.js` |

改完跑：

```bash
cd _build && node all.js
```

自检查三样：本地引用有没有坏链、JS 有没有语法错、每页是不是恰好一个 h1。
**最后一行是 `✅ 全部通过` 才算完。**

本地验一眼：

```bash
python3 -m http.server 8899   # 在仓库根目录
```

重点看：图标有没有出来、点开「判断训练」题库能不能加载、手机宽度下排版有没有塌。
